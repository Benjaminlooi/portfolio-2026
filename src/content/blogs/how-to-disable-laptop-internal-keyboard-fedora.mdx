My laptop keyboard has degraded over the years. Heat made the keys harder to press, and some key clips broke. I wanted to place my mechanical keyboard on top of the laptop, but the built-in keyboard kept firing random keypresses. I tested this fix on Fedora 41 and 42 running Wayland.

This method sets `LIBINPUT_IGNORE_DEVICE=1` for the selected keyboard. [Libinput documents this property](https://wayland.freedesktop.org/libinput/doc/latest/ignoring-devices.html) as a way to exclude a device from libinput; it does not disable the keyboard in firmware or every other input stack.

## What You'll Need

- A working external keyboard, connected before applying the rule
- **Terminal access** with `sudo` privileges
- The commands: `libinput`, `udevadm`, and a text editor (e.g. `nano` or `vim`)

## Step 1: Identify Your Built-In Keyboard

Open a terminal and type:

```bash
sudo libinput list-devices
```

Scroll until you see something like:

```
Device:           AT Translated Set 2 keyboard
Kernel:           /dev/input/event3
```

On my laptop, the built-in keyboard is named "AT Translated Set 2 keyboard". Yours may differ. Identify your internal keyboard and note its exact name and `eventX` number; do not copy the example blindly. Event numbers can change after a reboot.

## Step 2: Double-Check with `udevadm`

Confirm its properties:

```bash
udevadm info /dev/input/event3
```

You should see lines like:

```
E: NAME="AT Translated Set 2 keyboard"
E: ID_INPUT_KEYBOARD=1
```

If you do not see the expected keyboard properties, check the device again. To inspect the parent attributes used by `ATTRS{name}` in the rule below, run:

```bash
udevadm info --attribute-walk --name=/dev/input/event3
```

Look for the matching `ATTRS{name}` value. The [udevadm manual](https://www.freedesktop.org/software/systemd/man/latest/udevadm.html) explains the property query and attribute walk.

## Step 3: Write the udev Rule

Create a new rule file:

```bash
sudo nano /etc/udev/rules.d/99-disable-internal-keyboard.rules
```

Paste in this one-liner (adjust the name exactly if yours differs):

```udev title="99-disable-internal-keyboard.rules"
ACTION=="add|change", ATTRS{name}=="AT Translated Set 2 keyboard", ENV{ID_INPUT_KEYBOARD}=="1", ENV{LIBINPUT_IGNORE_DEVICE}="1"
```

This tells libinput to ignore that device.

## Step 4: Reload the Rule and Verify It

Reload the rules and trigger a change for the keyboard you identified:

```bash
sudo udevadm control --reload-rules
sudo udevadm trigger --action=change /sys/class/input/event3
udevadm settle
udevadm info --query=property --name=/dev/input/event3
```

Replace `event3` with your keyboard's current event number. Look for:

```text
LIBINPUT_IGNORE_DEVICE=1
```

Reloading rules alone does not apply them to existing devices; triggering an event lets udev process the device again. See the [udevadm manual](https://www.freedesktop.org/software/systemd/man/latest/udevadm.html).

**The property appearing does not guarantee an immediate change in your desktop session.** Libinput reads these properties when it adds a device, according to its [configuration documentation](https://wayland.freedesktop.org/libinput/doc/latest/device-configuration-via-udev.html). Save your work and reboot if the keyboard still types, then test both keyboards.

## If the Built-In Keyboard Still Works

- **The property is missing:** check the keyboard name, event number, and rule filename. Inspect rule processing with `sudo udevadm test /sys/class/input/event3` and look for errors.
- **The property is present but typing still works:** reboot so the desktop initializes its input devices again.
- **Your laptop uses a different keyboard name:** use its actual parent attribute from Step 2. Do not broaden the rule to match every keyboard.

I tested this on Fedora 41 and 42 with Wayland. I have not verified it on Ubuntu or other distributions.

## Re-enable Your Laptop Keyboard

Remove the rule and reload udev:

```bash
sudo rm /etc/udev/rules.d/99-disable-internal-keyboard.rules
sudo udevadm control --reload-rules
sudo udevadm trigger --action=change /sys/class/input/event3
udevadm settle
```

Use the keyboard's current event number. Save your work and reboot if it remains ignored by the desktop session. Removing the rule reverses this guide's configuration; keep your external keyboard connected until the built-in keyboard works again.

Now I can place my external keyboard on top of the laptop and type without random input from the built-in keyboard.
